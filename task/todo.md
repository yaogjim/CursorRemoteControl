# Remote Control 黑盒验证、内部诊断、最小修复与复验执行清单

> 本清单用于验证 CursorRemote 的 Remote Control 网页是否能在获授权的工作区内，可靠地读取任务依据、判断状态并执行受限操作。执行顺序固定为：**先黑盒、后诊断、再最小修复、最后同路径复验**。
>
> 黑盒阶段只使用正式网页公开入口和页面实际可见、可访问的控件；不得读取本地文件、调用内部调试接口、强制显示隐藏控件、移除遮罩、绕过禁用状态或直接操作 Cursor DOM。内部诊断必须等到黑盒失败已被稳定记录后才能开始。源码测试、模拟结果和历史候选实例结果均不能替代当前运行实例的黑盒证据。

## 全程约束

- [ ] 仅操作用户明确授权的工作区、窗口、会话、动作和通知渠道；扩大范围必须重新取得授权。
- [ ] 写操作前确认目标、授权版本、控制版本、内容版本和动作前提仍有效；任何一项未知都停止写入。
- [ ] 不在真实任务中制造错误，不批准未知命令，不切换未授权模式或模型，不把问卷推荐项当作用户授权。
- [ ] 每个请求使用唯一 `commandId`，记录观察时间、目标身份、请求与响应；结果未知时禁止换标识重发。
- [ ] 区分“代码已实现、隔离测试通过、历史候选实测、当前部署实测”，不得互相替代。
- [ ] 日志和证据必须脱敏；不得记录密码、会话令牌、Bearer、Cookie、Bot Token、完整对话或无关代码。
- [ ] 任一停止条件触发时保留现场，记录“未验证”或“结果未知”，不得为了得到通过结论继续试错。

## 第一段：确认授权、目标与停止条件

**目的：** 在接触 Remote Control 前固定本轮允许观察和操作的边界。

- [ ] 记录测试人、批准人、开始时间、预计结束时间和本轮执行人。
- [ ] 记录获授权的工作区稳定身份、窗口、会话、测试任务和允许读取的范围；标题只能作为展示信息，不能作为唯一身份。
- [ ] 记录允许的写操作、最大操作次数、最小间隔、总时限，以及允许的模式、模型和费用边界。
- [ ] 记录是否允许低风险消息、明确错误恢复、Web/Telegram 通知、人工接回和重启演练；未明确授权的项目一律跳过。
- [ ] 准备唯一测试标识；测试消息必须可与真实任务内容清楚区分，且不触发文件修改、命令执行、审批或外部副作用。
- [ ] 明确停止条件：目标身份不明、版本不明、权限过期、出现草稿或人工操作、结果未知、连接/提取数据过期、页面要求绕过正常控件、可能影响真实任务。

**本段完成证据：** 一份带时间的授权摘要和目标摘要；缺少任一必填边界时，本轮只允许只读检查。

## 第二段：建立当前运行实例基线

**目的：** 证明本轮验证针对哪个实例、哪个构建和哪个观察窗口。

- [ ] 从正常产品入口记录 Remote Control URL、服务实例标识、产品版本、构建摘要和启动时间；页面未公开的字段标为“黑盒不可见”，不得在本段用内部信息补齐。
- [ ] 记录浏览器、操作系统、网络入口、认证方式和测试时钟时区。
- [ ] 记录页面初始的连接状态、提取健康、内容观察时间、目标窗口和会话显示信息。
- [ ] 截取脱敏的初始页面证据，并保存每个页面请求对应的 `commandId` 或请求时间。
- [ ] 确认测试过程中实例未重启、构建未替换、登录身份未变化；发生变化时废止旧基线并重新开始本段。

**本段通过条件：** 后续每条证据都能关联到同一运行实例和观察窗口。无法确认时结论只能写“当前实例未验证”。

## 第三段：验证登录、连接与只读降级

**目的：** 从外部用户视角确认 Remote Control 可进入、可识别连接异常，并在证据不足时安全降级。

- [ ] 使用正常登录流程进入页面，不复用内部管理会话，不把长期密钥放入 URL。
- [ ] 验证成功登录后能看到连接状态；失败登录不泄露密码、令牌、内部路径或堆栈。
- [ ] 在不制造故障的前提下观察已有的断开、提取失败或过期状态；确认页面区分 Remote Control 服务、Cursor/CDP、内容提取和监督检查活性。
- [ ] 确认状态过期、目标不明或提取失败时，写入口被禁用并显示可理解的原因，只读安全快照仍按授权提供。
- [ ] 恢复或刷新后重新读取完整状态，不以“页面重新连上”推断旧操作已经完成，也不自动重放写操作。

**本段通过条件：** 登录和连接状态可解释，异常时失败关闭；若没有自然出现的断连样本，只记录正常路径通过，断连路径保留“未验证”。

## 第四段：验证工作区、窗口与会话目标

**目的：** 证明读取和后续操作绑定到正确目标，而不是碰巧处于当前活动页。

- [ ] 核对页面展示的工作区身份、窗口身份、稳定会话身份和当前任务归属；核对 Current、Open、History 仅表示呈现位置，不代表授权。
- [ ] 在授权范围内通过正常菜单查看会话列表，确认未授权会话不会因“可见”自动获得读取或操作权限。
- [ ] 切换到目标后等待新的目标状态和观察时间，再核对工作区、窗口、会话及任务；不得沿用切换前快照。
- [ ] 发现同名工作区、多根工作区、远程工作区、会话重连或新建会话时，要求稳定身份能够区分；只能看到标题时停止写入。
- [ ] 页面目标意外变化、出现用户草稿或桌面人工交互迹象时立即让权，不强行切回原界面。

**本段通过条件：** 目标可稳定确认，切换后数据不串会话；身份不足时只读降级并记录缺失字段。

## 第五段：验证任务依据与计划全文可读

**目的：** 完成“仅凭 Remote Control URL 读懂目标与计划”的核心黑盒验证。

- [ ] 仅通过网页读取目标、约束、验收条件、计划全文、任务进度、关键人工决策和尚待交互内容。
- [ ] 核对每类依据的来源、工作区/会话/任务归属、版本或摘要标识、更新时间、观察时间和完整性状态。
- [ ] 对计划正文分别核对开头、中间和末尾，并核对 todo 数量、顺序、状态及计划版本；`Created Plan`、标题、摘要或当前聊天回复都不能代替全文。
- [ ] 检查页面是否明确显示未加载历史、扫描范围、分页、截断、部分、缺失或未知；静默截断判定为失败。
- [ ] 在目标不变的情况下重复打开同一计划，确认仍指向同一版本；版本变化后，旧引用和依赖旧版本的待执行动作必须失效。
- [ ] 计划缺失时确认页面保持只读，并给出有界、可理解且不泄露本地路径的失败原因。

**本段通过条件：** 外部阅读者无需本地文件或用户粘贴即可核对全文首/中/末、版本、目标和任务状态。安全显示“缺失”只证明降级正确，不算全文可读通过。

## 第六段：验证状态解释与新鲜度

**目的：** 确认页面不会把界面信号误报为任务结论。

- [ ] 分别记录连接健康、提取健康、内容观察时间、内容变化时间、最近进展时间和监督检查时间。
- [ ] 核对页面能区分：运行且有进展、运行但暂无新输出、待审批、待用户选择、当前明确错误、遥测过期/提取失败、完成声明待验收、已验收完成和未知。
- [ ] 确认 `Idle`、固定时间无输出或没有状态补丁只触发重新检查，不直接表示完成、失败或卡住。
- [ ] 确认隐藏文案、折叠历史、旧会话错误和被引用的报错文本不会被当作当前错误。
- [ ] 所有派生判断都应显示目标、来源、观察时间和简短依据；证据冲突或不足时必须显示“未知”。
- [ ] 任务声称完成时仍进入待人工验收，不能由 Remote Control 自动结束托管。

**本段通过条件：** 状态结论可追溯且保守；任何无法解释的乐观推断均判定为失败。

## 第七段：验证一次获授权的低风险交互

**目的：** 证明一次写请求到达正确会话，并用分层证据判断结果。

- [ ] 仅在前六段通过且已取得单次写授权时执行；否则本段标为“未获授权，未执行”。
- [ ] 发送带唯一测试标识的无副作用消息，记录同一个 `commandId`、目标身份、授权版本、控制版本和发送前内容版本。
- [ ] 分别核对“Remote Control 已接收”“已派发”“正确会话出现目标侧证据”“出现与本次交互相关的预期进展”；不得把点击、按键或 socket 回执直接写成执行成功。
- [ ] 确认目标会话只出现一次测试消息；页面重连、响应超时或刷新不得导致重复发送。
- [ ] 若目标侧确认超时，先回读同一会话和原操作记录；仍无法确认时标记“结果未知”，立即停止写入并禁止更换标识重发。
- [ ] 操作后再次核对目标、草稿、任务状态和人工接回状态，避免后续动作沿用过期前提。

**本段通过条件：** 同一操作具有完整分层回执，目标正确且只执行一次。只收到服务端回执或只能证明按下 Enter 均不算通过。

## 第八段：验证错误恢复、人工决策与接回边界

**目的：** 在有独立授权和自然样本时验证恢复闭环；不为了验收主动破坏真实任务。

- [ ] 仅处理当前、明确、归属于授权目标且可恢复的自然错误；没有合适样本时标记“未验证”，不得制造故障。
- [ ] 错误恢复前记录错误证据、目标、内容版本、已尝试动作和唯一问题标识；旧错误和能力完整性未知不得触发恢复。
- [ ] 需要人工决定时，确认该工作区自动写入和有副作用巡检已暂停；通知包含问题标识、证据、版本、风险、推荐方案和有效期。
- [ ] 区分通知待发送、渠道接受、送达未知、用户确认和最终回执；渠道 API 成功不得写成用户已读。
- [ ] 用户决定必须绑定问题、版本、目标和有效期；执行前重新读取目标和动作，旧回复、无关联“继续”或内容已变化均不得执行。
- [ ] 验证人工接回会取消确定未派发的自动操作；已派发动作只报告事实，不宣称撤回，也不宣称已停止 Cursor 正在运行的工作。
- [ ] 恢复成功后核对错误消失及新进展；结果未知时停止，不重放旧动作。

**本段通过条件：** 获授权的子场景具备问题记录、有效决定、重新核对、单次执行和最终回执。未授权或无自然错误样本不构成失败，但必须明确保留待验收。

## 第九段：固化黑盒结果并建立诊断门

**目的：** 在查看内部实现前形成不可被后续知识污染的黑盒记录。

- [ ] 为第一至第八段逐项标记“通过、失败、未验证、结果未知”，并记录观察事实，不先写根因猜测。
- [ ] 保存最小失败复现：入口、前置状态、目标、操作步骤、预期、实际、时间、`commandId`、页面可见错误和脱敏截图。
- [ ] 确认失败至少可重复一次，或已有足够证据说明再次执行会产生副作用；禁止为稳定复现而重复未知写操作。
- [ ] 将页面缺陷、服务不可达、目标身份不足、数据缺失、操作未知和授权不足分别分类，避免把所有问题归为“计划读取失败”。
- [ ] 写明诊断准入理由和允许查看的内部范围；黑盒已通过的路径不得为了优化而顺带修改。

**本段完成条件：** 存在独立的黑盒结论和最小复现。没有失败时跳过第十至第十二段，直接进入第十三段做重复复验。

## 第十段：沿数据链进行只读内部诊断

**目的：** 定位失败发生在 Cursor 原始数据、提取、状态、传输、安全校验还是前端呈现中的哪一层。

- [ ] 先探测 Cursor 当前是否提供直接、稳定、可关联的数据，如工具身份、计划文档引用、会话身份或工作区 URI；不得先用标题或 `Created Plan` 文案猜文件。
- [ ] 在同一目标和相邻观察窗口依次核对：Cursor 原始可见数据 → DOM 提取结果 → 状态管理器快照/补丁 → Relay 出站数据 → 浏览器接收数据 → 页面可见呈现。
- [ ] 对全文读取单独核对：计划发现引用、socket 绑定、目标代次、登录身份、有效期、文件定位、允许目录、文件类型、大小限制、版本摘要和失败阶段。
- [ ] 对写操作单独核对：授权校验、控制版本、目标代际、持久安全记录、最终派发、目标侧确认和预期进展；不得用内部“调用成功”覆盖目标侧未知。
- [ ] 对状态误判核对原始信号与派生状态，区分提取时间、内容变化时间、进展时间及陈旧化逻辑。
- [ ] 诊断命令保持只读、有界、脱敏；不得扫描无关会话、枚举计划目录或打开跨工作区文件。

**本段完成证据：** 一条带时间和目标身份的数据链，明确最后一个正确层和第一个错误层；无法定位时保持“根因未知”。

## 第十一段：形成根因结论与最小修复边界

**目的：** 在改代码前证明修复对象和允许改动范围。

- [ ] 用证据描述根因，格式为“在什么目标和版本下，哪一层丢失/误判/拒绝了什么数据，导致什么外部现象”。
- [ ] 列出已排除的相邻原因，并注明排除证据；不得把相关性、日志缺失或等待时间当作根因。
- [ ] 明确最小修复层：原始数据关联、提取、类型/状态、Relay、安全校验或前端呈现，只修改能够解释黑盒失败的层。
- [ ] 写明不得改变的契约：授权边界、目标绑定、版本失效、幂等、失败关闭、旧客户端兼容、扩展与服务端边界。
- [ ] 定义修复后的可观察结果、回归风险、回滚开关或恢复方式，以及必须新增的失败用例。
- [ ] 根因证据不足时回到第十段补证据；不得用放宽目录、延长等待、增加无界扫描、硬编码标题或自动重试掩盖问题。

**本段通过条件：** 修复范围能由黑盒失败和内部证据共同推出，且没有扩大读取、写入或重试权限。

## 第十二段：实施最小修复并完成隔离验证

**目的：** 用最小代码变化修复已证实断点，同时守住安全与兼容边界。

- [ ] 只修改第十一段批准的模块；接线仍集中在组合根，模块间沿用既有事件通信，不把服务端逻辑迁入 Extension Host。
- [ ] DOM 或解析变更必须先有直接探测证据，并优先使用稳定结构化属性；非消息选择器继续从既有选择器配置读取。
- [ ] 新增针对真实失败形态的自动化测试，同时覆盖目标变化、版本变化、缺失/部分数据、过期引用、错会话、重复请求和结果未知等相邻安全分支。
- [ ] 保持旧 Web/Telegram 流程可用；需要协议扩展时采用兼容字段或能力协商，不静默改变旧语义。
- [ ] 依次运行相关定向测试、完整 `npm test`、`npx tsc --noEmit`、`node --check src/client/app.js`、`npm run build`、`npm run build:ext` 和 `git diff --check`。
- [ ] 记录实际命令、退出码、测试数量、构建产物摘要和未执行项；测试未运行或失败不得写成通过。

**本段通过条件：** 新失败用例先能证明旧行为不满足预期，修复后相关回归和完整构建均通过；若只能模拟通过，必须继续标注当前实例尚未复验。

## 第十三段：部署同一产物并执行同路径黑盒复验

**目的：** 证明修复后的实际运行实例解决原问题，而不是只在源码或测试环境成立。

- [ ] 部署第十二段验证过的同一构建产物，记录新的实例标识、版本、构建摘要和启动时间，并确认未误连旧实例。
- [ ] 不查看内部诊断数据，重新按第二至第八段的正常网页路径执行；使用与失败复现相同的目标类型、入口、前置状态和核对点。
- [ ] 对计划读取重新核对正文首/中/末、todo、版本、完整性和旧引用失效；不得只验证标题或摘要出现。
- [ ] 对获授权写操作使用新的唯一标识且最多执行一次；原操作结果未知时，不以“复验”为由重发原业务动作。
- [ ] 重复核对错目标、过期状态、权限撤销、人工接回和重连后的失败关闭，确认修复没有放宽安全边界。
- [ ] 将修复前后页面证据按同一观察口径对照；若实例、目标或版本不同，明确说明可比性限制。

**本段通过条件：** 原黑盒失败在当前部署中按相同路径消失，相关安全降级仍有效。自动化测试通过但黑盒未通过时，修复仍视为未完成。
